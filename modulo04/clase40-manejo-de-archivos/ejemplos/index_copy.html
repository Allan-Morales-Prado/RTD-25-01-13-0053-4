Documentación de la función open() en Python

Traducción al español

(función) def open(
    file: FileDescriptorOrPath,
    mode: OpenTextMode = "r",
    buffering: int = -1,
    encoding: str | None = None,
    errors: str | None = None,
    newline: str | None = None,
    closefd: bool = True,
    opener: _Opener | None = None
) -> TextIOWrapper[_WrappedBuffer]

Abre un archivo y devuelve un flujo de datos (stream). Lanza OSError en caso de fallo.

file es una cadena de texto o de bytes que proporciona el nombre (y la ruta si el archivo no está en el directorio de trabajo actual) del archivo a abrir, o un descriptor de archivo entero del archivo a envolver. (Si se proporciona un descriptor de archivo, se cierra cuando el objeto E/S devuelto se cierra, a menos que closefd se establezca como False).

mode es una cadena opcional que especifica el modo en el que se abre el archivo. Su valor predeterminado es 'r' que significa abrir para lectura en modo texto. Otros valores comunes son 'w' para escritura (truncando el archivo si ya existe), 'x' para crear y escribir en un archivo nuevo, y 'a' para añadir (que en algunos sistemas Unix, significa que todas las escrituras se añaden al final del archivo independientemente de la posición actual del puntero). En modo texto, si no se especifica encoding, la codificación utilizada depende de la plataforma: se llama a locale.getencoding() para obtener la codificación regional actual. (Para leer y escribir bytes sin procesar, use el modo binario y no especifique encoding). Los modos disponibles son:

Carácter Significado
'r' Abrir para lectura (predeterminado)
'w' Abrir para escritura, truncando el archivo primero
'x' Crear un nuevo archivo y abrirlo para escritura
'a' Abrir para escritura, añadiendo al final del archivo si existe
'b' Modo binario
't' Modo texto (predeterminado)
'+' Abrir un archivo en disco para actualización (lectura y escritura)

El modo predeterminado es 'rt' (abrir para lectura de texto). Para acceso aleatorio binario, el modo 'w+b' abre y trunca el archivo a 0 bytes, mientras que 'r+b' abre el archivo sin truncamiento. El modo 'x' implica 'w' y lanza un FileExistsError si el archivo ya existe.

Python distingue entre archivos abiertos en modo binario y de texto, incluso cuando el sistema operativo subyacente no lo hace. Los archivos abiertos en modo binario (añadiendo 'b' al argumento mode) devuelven el contenido como objetos bytes sin decodificación. En modo texto (el predeterminado, o cuando se añade 't' al argumento mode), el contenido del archivo se devuelve como cadenas (strings), habiendo sido decodificados primero los bytes usando una codificación dependiente de la plataforma o usando la codificación especificada si se proporciona.

buffering es un entero opcional que se utiliza para establecer la política de almacenamiento en búfer. Pase 0 para desactivar el almacenamiento en búfer (solo permitido en modo binario), 1 para seleccionar almacenamiento en búfer por líneas (solo usable en modo texto), y un entero > 1 para indicar el tamaño de un búfer de bloques de tamaño fijo. Cuando no se proporciona el argumento buffering, la política de almacenamiento en búfer predeterminada funciona de la siguiente manera:

  • Los archivos binarios se almacenan en búfer en bloques de tamaño fijo; el tamaño del búfer es max(min(tamaño_bloque, 8 MiB), DEFAULT_BUFFER_SIZE) cuando el tamaño del bloque del dispositivo está disponible.
  • En la mayoría de los sistemas, el búfer típicamente será de 128 kilobytes de longitud.
  • Los archivos de texto "interactivos" (archivos para los cuales isatty() devuelve True) usan almacenamiento en búfer por líneas. Otros archivos de texto usan la política descrita anteriormente para archivos binarios.

encoding es el nombre de la codificación utilizada para decodificar o codificar el archivo. Esto solo debe usarse en modo texto. La codificación predeterminada depende de la plataforma, pero se puede pasar cualquier codificación soportada por Python. Consulte el módulo codecs para la lista de codificaciones soportadas.

errors es una cadena opcional que especifica cómo deben manejarse los errores de codificación; este argumento no debe usarse en modo binario. Pase 'strict' para lanzar una excepción ValueError si hay un error de codificación (el valor predeterminado None tiene el mismo efecto), o pase 'ignore' para ignorar los errores. (Tenga en cuenta que ignorar errores de codificación puede llevar a pérdida de datos). Consulte la documentación de codecs.register o ejecute help(codecs.Codec) para obtener una lista de las cadenas de error de codificación permitidas.

newline controla cómo funcionan los saltos de línea universales (solo aplica al modo texto). Puede ser None, '', '\n', '\r' y '\r\n'. Funciona de la siguiente manera:

  • En entrada, si newline es None, el modo de saltos de línea universales está habilitado. Las líneas en la entrada pueden terminar en '\n', '\r' o '\r\n', y estas se traducen a '\n' antes de ser devueltas al llamador. Si es '', el modo de saltos de línea universales está habilitado, pero los finales de línea se devuelven al llamador sin traducir. Si tiene cualquiera de los otros valores legales, las líneas de entrada solo terminan con la cadena dada, y el final de línea se devuelve al llamador sin traducir.
  • En salida, si newline es None, cualquier carácter '\n' escrito se traduce al separador de línea predeterminado del sistema, os.linesep. Si newline es '' o '\n', no se realiza ninguna traducción. Si newline es cualquiera de los otros valores legales, cualquier carácter '\n' escrito se traduce a la cadena dada.

Si closefd es False, el descriptor de archivo subyacente se mantendrá abierto cuando el archivo se cierre. Esto no funciona cuando se proporciona un nombre de archivo y debe ser True en ese caso.

Se puede usar un opener personalizado pasando un objeto invocable como opener. El descriptor de archivo subyacente para el objeto archivo se obtiene llamando a opener con (file, flags). opener debe devolver un descriptor de archivo abierto (pasar os.open como opener resulta en una funcionalidad similar a pasar None).

open() devuelve un objeto archivo cuyo tipo depende del modo, y a través del cual se realizan las operaciones estándar de archivo como lectura y escritura. Cuando open() se usa para abrir un archivo en modo texto ('w', 'r', 'wt', 'rt', etc.), devuelve un TextIOWrapper. Cuando se usa para abrir un archivo en modo binario, la clase devuelta varía: en modo de lectura binaria, devuelve un BufferedReader; en modos de escritura binaria y adición binaria, devuelve un BufferedWriter, y en modo de lectura/escritura, devuelve un BufferedRandom.

También es posible usar una cadena (string) o bytearray como un archivo tanto para lectura como para escritura. Para strings, StringIO puede usarse como un archivo abierto en modo texto, y para bytes, BytesIO puede usarse como un archivo abierto en modo binario.

Resumen de los modos más importantes

Modo Descripción
'r' Lectura (predeterminado)
'w' Escritura, truncando el archivo primero
'x' Crear nuevo archivo y abrirlo para escritura (lanza FileExistsError si existe)
'a' Escritura, añadiendo al final del archivo si existe
'b' Modo binario
't' Modo texto (predeterminado)
'+' Actualización (lectura y escritura)

Combinaciones comunes:

  • 'rb': Lectura binaria
  • 'wb': Escritura binaria (trunca)
  • 'ab': Adición binaria
  • 'r+b': Lectura/escritura binaria (sin truncar)
  • 'w+b': Lectura/escritura binaria (trunca)
  • 'a+b': Lectura/escritura binaria (añade al final)

Valores predeterminados importantes

  • Modo predeterminado: 'rt' (lectura de texto)
  • Encoding predeterminado: Depende de la plataforma (locale.getencoding())
  • Buffering predeterminado:
    • Binario: bloques de tamaño fijo (~128 KB típicamente)
    • Texto interactivo (terminal): por líneas
    • Otros textos: igual que binario
  • Errors: None (equivalente a 'strict')
